# Limitations and responsible claims

- This is a working local research prototype with a deterministic simulator. It is not production-ready, and no novelty or universal protection claim is made.
- Screening uses explainable regex patterns, which miss paraphrases and can warn on benign quotations. Authorization does not depend on those warnings.
- Outgoing marker checks recognize configured plaintext synthetic patterns. Encoded, fragmented, transformed or unknown sensitive content may bypass detection. This is not complete DLP. The default pattern is always preserved by the policy editor.
- Classification is a directory convention (`confidential/`), not semantic classification. Sandbox fixtures are synthetic text only; there is no PDF parser, general upload pipeline, unrestricted shell, browser tool or external HTTP tool.
- File validation and execution are separate operations. Concurrent hostile filesystem replacement is outside the static-lab threat model; this is not an OS-level race-proof sandbox. Junction handling is tested on Windows; symlink tests may skip when Windows lacks creation privilege.
- Only canonical local POST requests are supported. This deliberate restriction permits a safe exfiltration demonstration but does not implement a general Internet egress gateway. Loopback services are trusted laboratory components; another local process could impersonate them.
- A local password account, expiring cookie sessions, session-bound headers, origin/host validation and loopback binding protect the intended single-user demo. Cookies use Secure=false for the intended loopback HTTP deployment; a remote deployment would need HTTPS and stronger identity controls. Login throttling is process-local and resets on restart. Local owner access is trusted for password recovery. They are not enterprise identity, RBAC or remote-user authentication. The same local OS user is trusted. Never expose the development servers publicly.
- Policy editing trusts the local human administrator. Regex pattern customization is not safe against a malicious administrator crafting pathological regexes. Defaults are bounded simple patterns; general untrusted regex configuration needs a linear-time engine and stronger limits.
- Policies reset to defaults on restart; policies are editable in memory, and the sample JSON is an export, not an auto-loaded configuration source. No per-run immutable policy snapshot is implemented yet. Preserve policy separately for research reproduction.
- Approval consumption is at-most-once and fail-closed. Crashes after consumption can lose an action; there is no distributed exactly-once execution. No expiry, multi-user identity, external notification or durable job resumption is provided. The current approval case is one action, so continuation of a multi-step paused agent is not implemented.
- Logs redact configured synthetic markers, not arbitrary personal data. No real documents should enter the lab. SQLite has no encryption or authenticity guarantee, and a privileged actor can edit history. Dashboard lists are capped at the latest 1,000 runs/events; exports from that view share that cap. The CLI retains its complete experiment rows in its own JSON.
- Optional real-model code is protected and step-limited, but requires a separately configured local runtime/model. Mock tests verify its request/enforcement wiring; without an available model, no live integration or model robustness claim can be made. Real-model event runs are separate from the simulated run table and metrics.
- Docker configuration is optional and requires independent runtime validation if Docker is unavailable. It uses ephemeral storage and a dedicated internal network, with no mounted personal files.
- Finite authored scenarios do not represent every attack. Held-out cases are a small independent synthetic set, not an established benchmark. A dissertation needs literature review, broader datasets, statistical analysis and independent replication to support stronger claims.
